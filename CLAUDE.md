# Global rules

- **New projects get a .gitignore first.** When creating or scaffolding a project, running `git init`, or working in a repo with no `.gitignore`, load the `project-gitignore` skill and add or merge its security baseline **before the first commit**. Never commit `.env` files, keys, credentials or local cloud config. If one is already tracked, untrack it and tell the user to rotate the secret.
- **Agents can request new skills.** When any agent's report starts with a `NEEDS:` block, don't finish the gap yourself. Follow the `token-efficiency` skill, Orchestration → "`NEEDS:` in a report": agents check for missing skills before they start work. agent-factory proposes each requested item. **Hard stop:** show the proposal so the user can validate what the skill is, then Approve / Change / Cancel. Only approved items get built. Then SendMessage hands the task back to the same agent to start or resume.
- **Offer to refresh the vault notes after factory builds.** At the end of a turn in which agent-factory **built or improved** something (not proposals, reviews or cancels), ask once with AskUserQuestion: "Update the vault notes?" **Yes** / **Later**.
